# Recorded research detail

The research list opens the existing authenticated GET /research/runs/:id API. It shows original run identity/times/status, available error, spot candle provenance and separate USD-M context, recorded dataset hash/period, specialist observations, unchanged backtest metadata and source-event links. A historical result never implies current agent work, out-of-sample validation, paper performance or order approval. Missing evidence stays missing, including older unversioned results.

API identity/status/date/array/provenance checks fail closed. Failed access and malformed evidence clear the panel; no list-summary fallback is presented as complete evidence. Owned request generations prevent old responses from overwriting a newer selection or a closed dialog. Source values render with textContent, not HTML. The dialog pauses cosmetic movement and restores keyboard focus. Long hashes/source IDs and JSON wrap on narrow screens; no scene geometry or art changes.

The list retains the backend's newest-first order. Reading detail or source events cannot schedule work, change a memory or execute an order. This increment adds no endpoint, database schema, provider or activation. It does not implement a multi-year historical importer or retained research job recovery.

Validation includes source/missing/failure coverage, hostile text, wrong identity/authentication errors, source mismatch, stale response/close races, list order and focus. TEST_ONLY fixtures stay inside the isolated test harness. Browser inspection of desktop/mobile and authenticated hosted readiness remain separately required when browser access exists.
