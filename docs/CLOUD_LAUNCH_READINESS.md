# First online launch: preparation and remaining acceptance

The current package prepares a reviewed single-writer Docker release; it does not provision a cloud account, database, backups, deploy or enable paper execution. The human requested verification before beginning publication. Source/market adapters, deterministic risk, independent capital and original office art remain intact.

## Prepared artifacts

- `deploy/render.example.yaml`: proposed Render resources, JSON syntax valid as YAML. Keep it an example outside root automatic discovery. Explicit paid compute/storage, one instance, previews/auto-deploy off, 45-second platform shutdown allowance for the application's existing 30-second drain deadline. Its Docker command checks first-publication configuration before `exec` starts the normal runtime. Subsequent approved paper activation requires reviewing/removing this first-publication command; do not silently bypass it. No background/cron/AI services are created.
- `npm run check:cloud-config`: compiled, offline check of first-publication environment. Reports only fixed identifiers, never raw secret values. Requires production, exact HTTPS origin, PostgreSQL, valid platform port/virtual capital, explicit disabled evaluation/execution/autonomy flags and absence of unnecessary private/paid keys. A pass verifies configuration syntax/policy only, not connection, import or backups.
- `npm run check:cloud-service`: operator-triggered read-only HTTPS acceptance probe. Uses `PUBLIC_ORIGIN` and `APP_ACCESS_TOKEN` directly from the environment. Checks public health, office response, unauthenticated rejection, authenticated production diagnosis, actual source freshness and disabled execution/AI. Five GET requests, manual redirects, eight-second per-request timeout and 128KiB JSON ceiling; no login, mutation, task, account, memory, order or paid call. A pass is a momentary observation, not an uptime/restore guarantee. Malformed/network failures produce fixed check identifiers without printing source text or credentials.
- Production authentication now rejects non-origin URLs before PostgreSQL opens; paths, credentials, fragments, query strings and trailing slashes are invalid `PUBLIC_ORIGIN`. This prevents misconfigured browser origin matching. Malformed production PostgreSQL URLs produce a fixed error without including the input credentials; first-launch configuration rejects database query overrides other than the optional verified sslmode.
- Container health uses `/health/ready`. CI additionally exercises compiled launch checks and verifies that the built production image fails with missing prerequisites and contains the compiled tools/importer/reference art.

## Provider compatibility reviewed on 2026-10-03

Render's default rolling deploy overlaps writers; the existing PostgreSQL session advisory lock intentionally rejects a second writer. The proposed 1GB disk at `/app/storage` forces stop-before-start and a single instance, with brief planned downtime. Data remains in managed PostgreSQL. [Disk behavior](https://render.com/docs/disks).

The internal Render Postgres endpoint has a self-signed certificate incompatible with this application's enforced `verify-full`. Configure `DATABASE_URL` manually from the external direct hostname. Do not use Blueprint `fromDatabase.connectionString`, transaction pooling, an IP replacing the hostname, or disabled certificate checks. Set database external allowlist from the service's outbound CIDRs. These CIDRs are region-shared; TLS and credentials remain essential. [Database connections](https://render.com/docs/postgresql-creating-connecting), [outbound addresses](https://render.com/docs/outbound-ip-addresses).

The example creates the database with **no external access**, not an allow-all rule. After resource creation, update the allowlist deliberately before connection/import. If using the example as a Blueprint, maintain the updated allowlist in its approved deployment copy so a later sync does not close access. Origin/database/code are `sync:false`; no credentials, origin guesses or internal-URL interpolation are committed. The template inherits the selected Blueprint branch, so select the reviewed release explicitly instead of old main. Resource names must be unique in the workspace. Schema validation is useful but does not prove account entitlement, accepted pricing, network reachability or creation success. [Blueprint fields](https://render.com/docs/blueprint-spec).

## Not yet verified without a cloud account

No production TLS handshake, account/region market reachability, deployed source freshness, hosted browser access, restore drill, backup/alert automation, capacity benchmark or bill has been observed. Render Hobby paid PostgreSQL provides three-day PITR; created logical exports remain seven days. Daily export scheduling and external retention are additional configuration, not supplied by this template. A temporary recovery copy can incur separate compute/storage charges. [Recovery documentation](https://render.com/docs/postgresql-backups).

Existing limits remain: one writer with planned deployment downtime; snapshot/event persistence rather than a normalized distributed ledger; shared operator access code rather than per-user identity; research on demand rather than an automatically scheduled agent team. AI has no provider. No claim of live-money capability, flawless animation, uninterrupted availability or autonomous intelligence follows from this preparation.
